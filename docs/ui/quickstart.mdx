`@n3wth/ui` is a React design system built on Astryx. This page installs the current version and renders a working page with a site layout and a native control.

<Info>
  The package supplies components and styles. It does not create a router, fetch data, or supply an app shell.
</Info>

## Prerequisites

- **Node.js 24** (declared in the package `engines` field)
- **React and React DOM 18 or 19** (peer dependencies)
- A bundler that resolves ESM, package CSS imports, and font URLs. The package includes a Vite starter.

The example below assumes a React TypeScript app with `src/main.tsx` and an
HTML element with `id="root"`. For Next.js, put interactive components in
a client module and import the CSS through your application's global
stylesheet entry.

## Steps

<Steps>
  <Step title="Install the package">
    From your application directory, install `@n3wth/ui` at `^2.1.1`. React and React DOM are peer dependencies. GSAP is an optional peer (used by animation hooks).

    <CodeGroup>

    ```bash npm
    npm install @n3wth/ui@^2.1.1
    ```

    ```bash pnpm
    pnpm add @n3wth/ui@^2.1.1
    ```

    ```bash yarn
    yarn add @n3wth/ui@^2.1.1
    ```

    </CodeGroup>

    In this monorepo, use the root lockfile and keep workspace UI dependency versions aligned rather than installing a second registry copy.
  </Step>
  <Step title="Render a page">
    Replace `src/main.tsx` with this example. It mounts a provider, imports the shared stylesheet, and renders a counter with a native Astryx button.

    ```tsx
    import { useState } from 'react'
    import { createRoot } from 'react-dom/client'
    import {
      N3wthProvider,
      PageHeader,
      SiteContainer,
      SiteSection,
      SiteText,
    } from '@n3wth/ui/site'
    import { Button } from '@n3wth/ui/primitives'
    import '@n3wth/ui/site.css'
    
    function App() {
      const [count, setCount] = useState(0)
    
      return (
        <N3wthProvider mode="dark">
          <SiteContainer as="main">
            <PageHeader
              title="Component sandbox"
              description="Try a native control in the shared site theme."
            />
            <SiteSection aria-label="Counter">
              <Button label="Increment" onClick={() => setCount(value => value + 1)} />
              <SiteText as="div">
                <output aria-live="polite">Count: {count}</output>
              </SiteText>
            </SiteSection>
          </SiteContainer>
        </N3wthProvider>
      )
    }
    
    const root = document.getElementById('root')
    if (!root) throw new Error('Missing #root element')
    createRoot(root).render(<App />)
    ```
  </Step>
  <Step title="Start the dev server">
    Start the app with its existing development command, such as `npm run dev` in a Vite app. The page should display a heading and counter. Selecting **Increment** increases the count.

    `N3wthProvider` supplies the theme context. `site.css` supplies the generated theme and component CSS. You need both. This example does not require Tailwind utility generation.
  </Step>
</Steps>

## Font packaging caveat

<Warning>
  The public package does not include the workspace's licensed Suisse Intl font
  files. The theme references Suisse Intl for body and headings, but the release process deliberately excludes those commercial font files from the npm package.
</Warning>

The package ships these fonts in `public/fonts`: **Geist**, **GeistMono**, **MonaSans**, and **Satoshi**. Workspace apps additionally use **Suisse Intl**, which is not in the npm release. External consumers get a system-font fallback for Suisse; workspace apps supply the licensed files locally. If your bundler reports an unresolved font URL, see [font resolution fails](/ui/troubleshooting#font-resolution-fails).
