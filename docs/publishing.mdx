This documentation site is built with Mintlify. The source lives in [docs/](https://github.com/n3wth/n3wth/tree/HEAD/docs) inside the [n3wth/n3wth](https://github.com/n3wth/n3wth) repository, and `docs.json` controls the hosted site. Deployment is driven by the Mintlify GitHub App: pushes to `main` publish to [docs.n3wth.com](https://docs.n3wth.com).

<Note>
  Preview every change locally before merging. Mintlify's hosting connection is separate from the Vercel deployments used by the other apps in this repository.
</Note>

## Preview locally

Install the CLI once, then run it from the docs directory:

```bash
npm install -g mint
cd docs
mint dev
```

Open [http://localhost:3000](http://localhost:3000). The dev server hot-reloads MDX and `docs.json` changes.

## Check for broken links

Before opening a PR, verify internal links resolve:

```bash
cd docs
mint broken-links
```

Mintlify validates MDX and `docs.json` on save; a `mint dev` server that starts clean is a good signal. Preview representative pages across products, check navigation, code blocks, tables, mobile overflow, and both themes. A syntax check does not prove an example's API is correct, so verify code against the implementation too.

## Publish

Merging to `main` triggers the Mintlify GitHub App to build and deploy. The dashboard at [dashboard.mintlify.com](https://dashboard.mintlify.com) shows build status and previous deployments.

Every page must be listed in `docs.json`. Use root-relative paths for links inside the site (`/ui/quickstart`, not `/ui/quickstart.mdx`). Link to the [GitHub source](https://github.com/n3wth/n3wth) when describing code that lives outside `docs/`.

## Verify the published site

1. Confirm the deployment matches the merged commit in the Mintlify dashboard.
2. Load one page per product directly (not only through client-side navigation).
3. Test product navigation, page links, and search.
4. Confirm `/sitemap.xml` and `/llms.txt` are available.

## SEO

`docs.json` sets the shared metadata: `docs.n3wth.com` as the canonical origin and n3wth as the organization. Add page-specific `description`, `keywords`, `canonical`, or `noindex: true` in frontmatter when needed. See the [Mintlify SEO reference](https://mintlify.com/docs/settings/seo) for the full option list.

## Maintain accuracy

- Update examples when exports, command flags, or installation sources change.
- Keep internal plans and operational records outside `docs/`.
- Link separate runtime repositories (like [n3wth/r3](https://github.com/n3wth/r3)) instead of copying their release workflows here.
- Revert a broken documentation commit and verify the replacement deployment.
  Do not change application hosting settings to roll back a docs-only change.
